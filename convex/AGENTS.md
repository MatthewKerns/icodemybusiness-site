# convex/ — area rules

What you need to know to change this directory safely that the root `AGENTS.md` doesn't say.

- **Read `convex/_generated/ai/guidelines.md` first** — it overrides training-data Convex patterns.
- **Convex ships before the app.** Any change under `convex/` must be pushed to the deployment
  (`neat-hamster-414`) before a Next.js build that calls it goes live; the deploy script does this
  order automatically. Schema validation is on: new tables/fields must exist before writes.
- Never hand-edit `convex/_generated/`; it is regenerated by `npx convex dev --once` and committed.
- **Convex env is separate** from the VPS env: `ANTHROPIC_API_KEY`, `RESEND_API_KEY`, `RESEND_FROM_EMAIL`,
  `OWNER_EMAIL_DOMAINS`, `CLERK_JWT_ISSUER_DOMAIN` are set with `npx convex env set` (values never printed).
- Owner-only functions go through `requireOwner`; public queries must never return `internalBrief`
  or other admin-only fields.
- Every email send records an `emailSends` row (`emailSends.record`) — success and failure.
- Rate-limit anything a visitor can trigger (`convex/lib/rateLimits.ts`).
- Tests: `convex-test` with `convexTest(schema, modules)`; the deploy-time typecheck **includes**
  `*.test.ts` — a type error in a test blocks the push, and that is intended. Fix the helper, not the config.
